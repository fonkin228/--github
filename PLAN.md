# План разработки: калькулятор «Распределение пополнений»

## 0. Что делает продукт

Пополнения складываются в общую сумму. По каждому пополнению можно отметить
удержанную комиссию (по умолчанию 1%, настраивается) — она уменьшает только
этап «Заработок», на долю 1 и налог не влияет.

Сумма пополнений раскладывается на три части:

| Шаг | Формула в Excel | Что значит |
|---|---|---|
| Этап 1 | `Σ(пополнение)` | сумма пополнений, комиссия считается отдельно |
| Доля 1 | `CEILING(пополнения × 89%; 1000)` | 89%, округлённые **вверх** до кратности 1000 |
| Налог | `пополнения × 7%` | 7%, без округления |
| Заработок | `(пополнения − E − комиссия) × 4%` | 4% от остатка — **можно переводить себе** |
| Итого | `D + F + G` | сумма трёх частей |
| Резюме | `Доля 1 + Налог + Заработок` | итог распределения |

Плюс терпимый разбор ввода (`706 945`, `706 945,50`, неразрывные пробелы, `₽`) и статус
«не распознано» вместо тихой ошибки.

## 1. Итерация 1 — техническая часть (готово в этом репозитории)

- [x] **Ядро расчёта** (`shared/`) — один и тот же TypeScript-код считает на сервере, в боте и в браузере. Формулы 1:1 с Excel, включая защиту от артефактов плавающей точки в `CEILING`.
- [x] **Разбор ввода** — пробелы всех видов, `₽`/`руб.`, `1 234 567,89`, `1.234.567,89`, `1,234,567.89`, отсев отрицательных и мусора.
- [x] **Backend** (Fastify) — API расчёта, настроек, истории, экспорта.
- [x] **Проверка подписи Telegram `initData`** (HMAC-SHA256 + контроль возраста) — без неё API открыт всему интернету.
- [x] **Хранилище** (SQLite) — пользователи, их параметры, история последних 100 расчётов.
- [x] **Экспорт в xlsx** (ExcelJS) — файл выгружается «живым»: проценты и шаг остаются в B5:B8 формулами, всё пересчитывается прямо в Excel. Структура повторяет исходник, включая скрытый служебный столбец L.
- [x] **Бот** (grammY) — `/start` с кнопкой Mini App, расчёт прямо из чата (в т.ч. списком), кнопка «Скачать xlsx», `/params`.
- [x] **Mini App** (React + Vite) — ввод сумм списком, живой пересчёт, редактируемые параметры, история, нативная тема и MainButton Telegram.
- [x] **Тесты** — 12 юнит-тестов на парсинг, округление, расчёт и целостность выгружаемого файла.
- [x] **Сверка с Excel** — сгенерированный файл пересчитан LibreOffice «с нуля»: цифры совпали до копейки.

**Контрольный пример** (N = 706 945): п.1 = 630 000 (+818,95 округление), п.2 = 49 486,15, п.3 = 28 245,04, итого = 707 731,19, Δ = +786,19.

База для п.3 переключается в «Параметрах»: `N − округление` (по умолчанию), `N` или `п.1`. Последний вариант — исходная формула таблицы, она давала недобор ≈0,44% от суммы.

## 2. Что нужно сделать тебе (по шагам)

### Шаг 1. Бот в BotFather (5 минут)
1. `/newbot` → имя и username → **скопировать токен**.
2. Пока ничего больше не настраивать — вернёмся сюда на шаге 4.

### Шаг 2. Публичный HTTPS (обязательно — Telegram не открывает Mini App по http)
Любой из вариантов:
- **Для теста прямо сейчас:** `npx localtunnel --port 3000` или `cloudflared tunnel --url http://localhost:3000` — получишь https-URL за 10 секунд.
- **Для боевого:** VPS + Caddy/nginx с Let's Encrypt, либо Railway / Render / Fly.io — там https из коробки.

### Шаг 3. Запуск
```bash
cp .env.example .env    # вписать BOT_TOKEN и WEBAPP_URL
npm install
npm run build           # собрать Mini App
npm start               # сервер + бот на одном порту
```

### Шаг 4. Привязать Mini App в BotFather
1. `/newapp` → выбрать бота → название, описание, иконка 640×360 → **Web App URL = твой https-адрес**.
2. `/setmenubutton` → выбрать бота → тот же URL → подпись кнопки, например «Калькулятор».
3. В `.env` вписать тот же адрес в `WEBAPP_URL` и перезапустить сервер.

### Шаг 5. Перед продом
- [ ] `ALLOW_DEV_AUTH=false` и `NODE_ENV=production` — иначе проверка подписи Telegram фактически выключена.
- [ ] `BOT_MODE=webhook` + `WEBHOOK_SECRET` (случайная строка) вместо polling.
- [ ] Бэкап `data/app.db` (обычный файл SQLite — достаточно копировать по расписанию).

### Шаг 6. Чек-лист тестирования
- [ ] `/start` → кнопка открывает Mini App.
- [ ] Ввод `706 945` → п.1 = 630 000, итого = 704 686,15.
- [ ] Ввод списком (несколько строк) → свод сходится.
- [ ] Мусорная строка → красная карточка «не распознано», остальные считаются.
- [ ] Изменить проценты → «Сохранить» → перезайти → параметры на месте.
- [ ] MainButton → файл приходит в чат.
- [ ] Открыть файл в Excel, поменять B5 с 89% на 90% → всё пересчиталось.
- [ ] История: расчёт открывается обратно в калькулятор.
- [ ] Тёмная тема Telegram → интерфейс читаемый.

## 4. Осознанные решения (чтобы не было сюрпризов)

**Файл доставляется ботом, а не браузерным скачиванием.** WebView внутри Telegram часто блокирует blob-загрузки. Поэтому основной путь — сервер собирает файл и бот присылает его документом в чат. Прямое скачивание (`POST /api/export`) тоже есть — оно работает в обычном браузере.

**Расчёт дублируется на клиенте и на сервере.** Один и тот же модуль из `shared/`: на клиенте — чтобы цифры менялись мгновенно без сети, на сервере — потому что клиенту доверять нельзя (в файл и историю попадает серверный расчёт).

**Округление сделано с допуском.** `CEILING(890000.0000000001; 1000)` в наивной реализации даст 891 000. В `ceilTo` значение, кратное шагу с точностью до 1e-9, считается уже кратным — добавка 0. Отдельный тест это стережёт.

**Выгружается «живой» файл, а не мёртвый дамп.** Формулы на месте, значения проставлены как кэш — файл открывается с готовыми числами и при этом пересчитывается при правке параметров.

**История хранится последними 100 записями на пользователя** — чтобы SQLite не рос бесконечно.

## 5. Что дальше (итерация 2+)

Отсортировано по соотношению «польза / трудозатраты»:

1. **Импорт xlsx/csv со списком сумм** — сейчас суммы вводятся руками; загрузка файла закроет пакетные сценарии. ~половина дня.
2. **Именованные пресеты параметров** — «Схема А 89/7/4», «Схема Б 90/5/5» вместо одного набора. ~половина дня.
3. **Экспорт в PDF / картинку** — чтобы отправлять клиенту, а не только в Excel.
4. **Inline-режим бота** — считать прямо в чужом чате: `@bot 706945`.
5. **Многопользовательский режим/роли** — если калькулятором будет пользоваться команда и нужна общая история.
6. **Аудит-лог и выгрузка за период** — если расчёты идут в документооборот.
